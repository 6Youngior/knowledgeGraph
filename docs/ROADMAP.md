# FinGragh Agent 开发计划

更新时间：2026-11-12。按阶段成果推进，不固定每个阶段占用几周；期末截止日期以课程通知为准。

本文件描述期末拟完成的工作，不代表其中的功能已经实现。现有版本的数据、功能和实验记录仍以 README 和对应文档为准。

## 项目目标

FinGragh Agent 面向人工智能产业股票的投资分析与量化研究。用户可以直接提出公司比较、行业判断、股票筛选、走势预测或策略验证问题；Agent 根据问题调用数据、知识图谱、预测模型和回测工具，形成可以检查依据和实际结果的研究输出。

主线为“分析股票池 → 形成预测或排序 → 检验策略表现”，覆盖芯片、服务器、光互联、数据中心、云与模型企业。研究可以涉及一组证券、某个细分方向或用户给定的名单，不要求先选择一只股票或输入一个事件。问答是使用方式，量化分析和预测是实际能力。

教师要求显式知识表示及其在下游任务中的实际作用，并要求知识抽取实验。跨来源融合、隐含关系、多跳推理、长期记忆和动态更新是可探索方向，不是需要逐项完成的功能清单。本项目优先检验产业关系信息对股票分析和预测是否有帮助；长期研究记忆作为扩展，不占据预测与回测的主要开发资源。

期末重点回答两个问题：

1. 公司、产品、业务及产业关系等图谱信息，能否在量价与可用财务数据之外，为 AI 股票的未来相对收益排序提供额外信息？
2. 同一批资料与预算下，图谱增强 Agent 的分析正确性、证据支持和任务完成效果，相比通用 Agent 或 RAG 有哪些可验证的改善及局限？

研究范围为大模型、GPU/芯片、服务器和云服务及其上市公司关联，可纳入 A 股、港股和少量美股核心企业。先建设可以批量更新的数据底座，同时定义实验，再完成独立产品与展示。

## 产品形态

目标入口为 `fingraph`，启动后显示 FinGragh Agent 的暖金色像素标识、模型、研究时点和输入区。复用 Pi 的输入、会话、流式输出和工具调用显示；Windows 当前通过项目内的 `fingraph.cmd` 启动。

问答自然展开，必要时才澄清比较对象、预测期限等关键条件。用户可以要求比较一组公司、筛选一个细分方向、查看预测排名，或回测一套选择规则。Web 展示股票池、指标比较、预测得分、收益与回撤，以及关系和原文证据。研究范围按证券集合或主题记录，不用单个股票代码代表整个会话。

首批命令：

| 命令 | 用途 |
|---|---|
| `/web` | 打开与当前研究会话关联的图谱和行情页面 |
| `/time YYYY-MM-DD` | 在指定截止日开始一次研究会话 |
| `/time live` | 切回当前资料研究模式 |
| `/report` | 导出当前研究的依据、判断和待核查事项 |

更改时间时应建立隔离的分析分支，不能把已经见过后续走势的对话直接带回早期。浏览器页面和终端共享会话标识、时间限制及研究对象。

目标 Demo 依次完成三个自然问题：

1. “比较 AI 股票池里芯片、服务器、光互联公司的经营与市场表现，哪些值得进一步研究？”
2. “按已有模型，对未来 5 个交易日的相对表现排序，说明用到了什么数据和产业关系。”
3. “把相同规则放到留出的历史区间验证，查看收益、回撤、换手和交易成本；再比较去掉图谱后的结果。”

LLM 负责理解问题、组织工具和解释结果，预测得分来自实际训练或明确定义的量化模型。不得把模型分数解释为未经校准的上涨概率。历史模式固定研究日期，先保存预测，再从隔离的结果页面查看后续表现。

这段流程是期末目标。当前已能查询公司产品、财务与事件证据；量化训练、图谱增强预测、回测和研究笔记的持久化尚未发布。

## 开源复用与技术选择

以下结论来自官方文档与源码核查，尚未进行完整集成验证。集成时锁定具体版本，避免随主分支更新。

| 模块 | 首选方案 | 项目需要补充的部分 |
|---|---|---|
| Agent 与 TUI | Pi；GenericAgent 参考其工具组织与流程经验 | 金融问答、模型调用、分析任务与结果联动 |
| 工具协议 | 官方 MCP SDK；Pi 已有 MCP 支持 | 金融问答所需的图谱、原文、财务、计算及研究记忆工具，统一时间规则 |
| 知识图谱与时间 | 现有 NetworkX 与显式 Schema；Graphiti/Neo4j 按查询和更新需求验证 | 产业关系、证券映射、证据、可用日期及图谱特征，不以更换数据库替代下游实验 |
| 量化模型与回测 | 首先验证 Qlib 的 LightGBM、因子、预测分析与组合回测；参考其 HIST 图关系模型 | AI 股票池与日期正确的数据适配、图谱特征、相同划分下的消融实验与研究工具 |
| 金融数据 | AKShare 财务/主营/行情接口，结合巨潮、交易所及公司原始披露；少量美股用 SEC 数据补充 | 研究证券池、财报原文、财务指标、采集记录和披露时间 |
| Web | 保留现有 React、React Flow 和 ECharts | 以问题与研究记录组织界面，图谱、时间轴、证据和行情联动 |
| 实验参考 | FinMultiHopQA、FinSearchComp，参考 GA 配套 RealFin 任务 | 与当前研究范围匹配的测试集和完整检索实验 |

已核查的 Pi 发布包为 `@earendil-works/pi-coding-agent@1.5.2`，要求 Node.js 22.19 或更新版本；本机 Node.js 24.11.0 满足这一要求。官方仓库现为 [earendil-works/pi](https://github.com/earendil-works/pi)。

Pi 官方扩展提供 `setHeader`、`setTitle`、`setFooter` 和 `registerCommand`，可以定制启动显示及命令。当前官方 CLI 支持 MCP；SDK 使用时需要显式加载相关扩展，不能假定创建 SDK 会话便自动具备 CLI 的全部能力。

优先用独立启动器和扩展完成定制，待验证后决定是否需要少量上游修改。启动器使用项目自己的资源和配置，不混用开发者个人的技能、会话及凭证。

Graphiti 已提供时间属性、增量知识处理和 MCP 参考实现，但这些能力不自动等于严格的股票历史回测。现有图谱可先为量化特征和解释服务；Graphiti 与数据库选型不作为跑通预测主线的前置条件。后续按实际查询和更新需求验证集成，不能仅因为框架可用就增加长期记忆等功能。

老师在选题说明中列出的 [GenericAgent](https://github.com/lsdefine/GenericAgent) 已核查 README、`agent_loop.py`、`agentmain.py`、`plugins/hooks.py`、`frontends/tui_v3.py` 和打包配置。它是 Python 项目，已有基于 prompt_toolkit/rich 的 TUI、插件钩子及分层记忆；其记忆思路包含将任务经验整理为可复用流程。调研时 main 指向 `68d996a4588210aacb39cf79a4974d2743316e64`。这些能力与金融事实的时序图谱分别负责不同工作，不能直接等同。

第一轮接入验证后选用 Pi：项目内安装已接通 OpenCode Go 的 `deepseek-v4.1-flash` 和官方 SDK 实现的金融研究 MCP，真实对话已调用事件、关系、来源和财务工具。自定义 TUI、`/web`、模型工具调用及后端连接分别经过验证。品牌通过官方扩展设置，未修改 Pi 安装包；个人技能、配置和会话与项目隔离。GenericAgent 保留为流程记忆设计参考。严格历史预测和完整研究会话同步仍待完成。

## 数据与知识记忆

### 投资研究的数据范围

按上市公司与证券组织资料，把大模型和算力产业事件连接到公司基本面及市场表现。模型卡、技术博客和版本说明是产业事件的补充资料，不能替代上市公司公告、财报和财务表。

| 数据 | 首批内容 | 在研究中的作用 |
|---|---|---|
| 公司与证券 | 公司名称与别名、证券代码、交易所、上市日期、业务与组织归属 | 确认消息所指主体、上市主体和事件发生时可交易的证券 |
| 原始披露 | 年报、中报、季报、招股书、业绩预告，以及合作、订单、投资和风险澄清公告 | 查证公司经营情况和关系依据，保留原文件、公告时间及页码 |
| 结构化财务 | 营业收入、净利润、毛利率、研发投入、经营现金流、现金与负债 | 了解经营状况，判断产业消息与实际业务是否相关 |
| 行业与产业关系 | 主营产品、业务收入构成、研发、产品适配、云接入、有明确披露的客户和供应关系 | 区分真实经营联系、技术联系与仅同属概念板块 |
| 新闻与产业事件 | 模型发布、芯片与服务器产品、云服务接入、商业合作、订单和澄清 | 发现新增事实并触发研究，关联和更新已有知识 |
| 历史市场数据 | 股票和基准日线、开高低收、成交量、交易日历、上市及停牌、复权方式 | 提供事件前市场背景，事后按统一窗口检验预测 |

财务数值必须保留指标定义、报告期、披露日期、单位、币种、来源和修订版本。报告期结束日不等于公开日；模拟 2026 年 2 月的事件时，不得使用后来才披露的上一年度年报或一季报。后续修订不能覆盖历史会话实际可见的版本。

图谱保存公司、产品、事件和有出处的关系，财务与行情按证券、报告期和交易日期存放在结构化表中，通过 ID 连接查询。价格序列和财务表不需要逐格拆成大量图节点。研究 MCP 同时提供这些数据的受控查询。

先以约 10 家核心上市公司验证公告原文、财务表、产业资料和行情能否完整衔接，再扩充证券池。新上市公司用招股书和已披露报告补充上市前经营历史，不补造上市前股价。首批优先解决 A 股与港股资料，再补少量美股核心企业。

### 扩量与质量

目前已有 40 家公司、96 份去重财报，图谱包含 86 个实体、106 条关系和 10 个产业事件；整批原文尚未全部入图。期末以 3,000—5,000 份有效去重原文为主要采集目标，评估继续扩到 10,000 份的可行性；核心证券池覆盖约 50—100 家上市公司，并保留与其相关的未上市研究主体。图谱向千级实体、万级有证据事实扩展。扩量同时检查公司、时间、资料类型和关系覆盖，按实际处理成本修订目标。

数据底座分两条路径：结构化资料提供证券、公司、行业、产品及有依据的产业关系；新闻、公告与年报正文用于抽取事件和新增事实。复用成熟数据接口与解析工具，通过统一 ID、去重、证据和时间规则汇合。结构化数据缺少历史依据时只用于当前研究，不能回填早期。

统计分别列出独立原文文档、正文切片、业务实体、去重关系事实、来源证据记录、事件和行情行数。只有列表标题、网页导航或重复转载不计入有效正文；行情不混入文档数量。财务和价格等序列优先按证券代码连接查询，避免为了增加图规模拆成大量没有研究价值的节点。

资料应覆盖同一对象的连续变化，而不只是增加公司介绍。包括模型发布、产品适配、云服务接入、组织归属、合作及澄清信息；同时保留共同提及但没有真实合作关系的样本。

优先扩充公告、财报与实际业务信息，再补充技术资料。分来源族与发布主体设置采集配额，防止某家厂商博客、量化模型卡或重复版本说明占据大部分资料。来源配额由首批金融数据试采结果确定。

第一轮采集得到 278 份候选正文，来源为技术博客、模型卡、软件发布说明和产品页，正文哈希、来源缓存及元数据一致性已独立检查。它只验证了批量采集的可行性，尚未补齐公告和财务数据，也没有进入正式图谱。模型创建时间已与当前模型卡正文时间分开；历史正文版本仍待获取。下一步优先验证约 10 家核心上市公司的原始披露、财务表与行情，再扩充证券池和资料量。

随后完成五家 A 股、港股公司的金融试采，并整理到 `data/finance/`：206 条财务记录、483 条主营构成、2,243 行股票日线、449 行指数日线。财务表是 2026-11-11 的当前聚合快照，没有历史修订版本。财报语料已进一步扩至 96 份，并从首轮 12 段开发文本审核采用 22 条关系证据，其中 1 条补充已有关系。

每份材料保留来源地址、发布主体、可核实的公开时间、采集时间、原文或缓存以及内容标识。关系记录证据和适用时间；组织归属到上市主体需要单独证据，不能把品牌、子公司和上市集团直接混为一体。

知识记忆分为三类：

- 来源事实：带证据和时间的公司、产品、业务及关系。新披露修订旧事实时保留版本，不能只覆盖当前值。
- 研究记录：问题、涉及的多个实体或主题、分析时点、判断、支持与反对证据、模型配置、尚待核查的条件，以及判断修订的原因。
- 方法与用户背景：可复用的研究步骤，以及用户明确提供的观察名单、偏好或模拟持仓。方法记忆不混入某次预测的事后答案，用户背景独立于公开金融事实。

研究记录以问题或研究主题组织，不要求围绕一只股票。更换会话后可以接着讨论同一行业或假设，也能解释“上次怎么判断、这次哪些资料改变了判断”。预测与分析意见单独保存，不能自动写成已证实的事实；复盘保留原判断及其结果，不把旧判断改写为事后正确答案。

历史研究分支记录模拟研究时点、真实创建时间、来源版本和分支标识。回退时间时建立干净会话，只能读取该时点可用的事实与兼容的分支记录；在今天生成的历史模拟记录明确标记为模拟，不伪称当时实际做过预测。未来行情和事后复盘结果经独立评估接口查看，不通过研究工具泄露。

研究记忆是辅助能力。主线优先完成可重复的数据、预测与评估；需要持续追踪判断时，再验收“提出假设 → 对比公司 → 保存依据 → 新披露后复核”的记忆流程。

## 量化任务与图谱作用

先以现有 A 股 AI 股票池扩至约 50—100 家，港股继续支持资料研究，预测与回测先在一个市场中跑通。初始主任务固定为未来 5 个交易日的相对收益排序；20 日窗口在相同流程验证后扩展。股票池选择时间、上市与退市、停牌、涨跌停、数据覆盖和缺失值需要记录，不用今天的行业标签无条件回填过去。

行情优先补齐连续历史日线和交易日历，财务与图谱信息按公开时间加入特征。只有当前快照的指标不进入早期训练或回测。行情、财务、实体关系与原文分别存储，通过稳定证券和公司标识连接。

先运行简单基准和 Qlib LightGBM，使用量价及当时可用的财务特征。图谱增强第一轮采用可解释的关系特征：主营环节与产品暴露、已披露业务关系、相关公司群体的滞后量价及经营信号等。只按有证据的关系聚合，不把共同提及、同属概念或技术适配当商业供货。数值、邻居权重和传播规则由代码计算并记录配置。

HIST 提供概念与股票共享信息的现成图模型，可在简单增强有效、数据覆盖足够后作第二方案。其示例包含专用概念矩阵、股票映射和较长训练历史，不直接适配当前证券池；输入映射必须重建，关系信息必须符合实验时点。先用简单方案确定增益来自信息，再决定是否需要更复杂模型。

量化主实验使用相同证券池、时间划分、模型家族和训练预算，比较“量价/财务基线”“增加行业分类的强基线”“增加图谱关系特征”。加入打乱关系或去掉关系类型的消融，检查增益是否真的来自结构。训练、验证、测试按时间划分，标准化只拟合训练段；按预测窗口剔除跨边界标签，重叠持有期和滚动结果如实处理。

报告 Rank IC、排序或方向效果，以及统一调仓规则、交易成本和可交易约束下的组合收益、回撤与换手。预测、证券选择和评估规则在查看测试结果前固定。数据条件允许时保存开发期间尚未到期的预测，随后补充真实结果。

Agent/RAG 的比较另在相同语言模型、原始资料、基础量化工具和预算下进行，检查研究答案、计算、证据及任务完成情况。量化模型的改善和 Agent 回答的改善分开解释，不能用不同模型或额外数据的差异宣称知识图谱优于 Codex/RAG。

## 实验设计

### 知识抽取

先完成开发样本核查，再另取约 80—100 段独立文本，由成员标注并交叉复核。按来源或事件划分开发集与测试集，避免同一公告的转载或改写分布到两侧。

分别检查实体链接与关系抽取，报告关系 Precision、Recall、F1，并分析组织名称、关系混淆、否定或共同提及等错误。评测范围需说明是否提供实体目录，区分原文事实抽取和上市主体映射。期中已撤回的旧汇总评分不作为基线结果复用。

### 研究问答与工具使用

主要对照使用同一模型、同一批原始资料、相同研究时点和相近的调用预算：

| 配置 | 资料使用方式 |
|---|---|
| 普通研究 Agent | 文档与行情工具，不提供图谱 |
| RAG Agent | 文本检索，提供合理的关键词、向量检索及时间过滤 |
| FinGragh Agent | 在相同能力上增加图谱查询与关系增强分析；研究记忆作为可选消融 |

增加去掉关系路径或研究记忆的消融实验，用于分析改善来自哪里。核心对照共用最终选定的框架，避免将不同框架或底层模型的差异归因于知识图谱。所有正式对照同样遵守时间限制；去掉时间过滤只用于泄漏诊断，不能与合法历史预测混算。Codex 可另做实际使用对比，单列模型、工具、资料与预算，不与受控实验混为一项结论。

项目测试集拟包含 80—120 道问题，覆盖简单事实、跨来源关联、历史时点、更新后改答、证据不足和计算。测试题及答案由来源独立核实，不直接把当前图谱输出当正确答案。保留开发集，按事件留出测试，完整报告各类结果和失败样例。

主要指标为答案正确率、比较与计算正确性、跨来源证据完整性、未来资料误用次数、更新后的修正是否正确、跨会话记忆召回，以及耗时和 token。需要输出证券集合的题目再计算集合 Precision/Recall。除查询成本外，分别记录采集、抽取、建图、记忆更新和索引成本，报告一次研究与多次复用的成本。主评分尽量根据人工核实的答案和可计算字段完成；模型评审只作辅助，并抽查其判断。

公开基准优先试用：

- [FinMultiHopQA](https://arxiv.org/abs/2510.02906v2)：金融跨文档、跨年份和跨公司的多跳问答，公开了 [数据与来源标注](https://huggingface.co/datasets/domyn/FinMultiHopQA)。适合验证证据组合；其论文的主要实验控制证据呈现方式，不等于完整的检索系统对比。使用时需另核实能否获取原始语料，不把正确答案或标准路径提前提供给检索器。
- [FinSearchComp](https://randomtutu.github.io/FinSearchComp/)：包含历史查询、多步调查和时效数据任务，可参考其问题设计与答案核查。范围涵盖全球及大中华市场，不是股票涨跌预测基准；先检查与现有工具及来源的匹配程度。

另已读取 GenericAgent 配套 [RealFin-Benchmark 的说明和任务文件](https://github.com/JinyiHan99/GA-Technical-Report/tree/main/datasets/realfin_benchmark)。文件中有 40 项任务，主要涉及股票筛选、技术指标和量化计算，8 项采用自动评分、32 项混合评分。其参考答案由 Agent 共识生成，部分评分项只检查文件、字段和执行过程，需结合原始数据复核；不能直接作为预测能力或本项目优于 Codex 的证据。可借鉴其任务与成本记录方式。

先试跑小样本，选择适合的一套做有限规模复现。说明抽样规则、样本数量和完整流程；抽样成绩不作为全量榜单成绩。公开基准用于外部验证，项目自己的时序事件测试仍需完成。

### 股票走势预测

先确定研究问题、候选证券的选择规则、预测时点及固定窗口，例如未来 5 个交易日相对对应市场基准的收益方向或证券排序，再运行模型。候选可以是一组公司或观察名单，不只由单条事件触发。预测记录需在查看后续行情前保存；测试保留没有显著上涨、下跌及证据不足的案例，不预先规定 GLM 发布后应得到上涨判断。

初期可比较方向或股票排序，并使用简单的市场基准、固定规则以及相同模型的 RAG 版本作对照。报告实际样本数和不确定性；预测表现与问答表现分别呈现。未经校准的模型自报百分比，不称为可靠上涨概率。若开展模拟交易，再统一规定成交时点、交易费用和可交易条件。

历史模式在服务端统一限制所有入口，包括来源、实体、关系、事件、行情、检索和研究记录。区分事实发生时间、公开时间和系统记录时间；没有历史版本依据的网页不能简单按当前内容回填。结果查看使用隔离的评估接口，Agent 不能通过工具取到后续价格。

工具过滤不能排除模型预训练中记住历史结果的可能。历史回放需明确这一限制；条件允许时，从开发期开始记录尚未发生结果的预测作为补充。[相关研究](https://arxiv.org/abs/2605.28359)

## 推进阶段与验收

以实际成果决定何时进入下一阶段，不按固定周数切换。数据采集、界面验证和评测准备可以并行；试验发现问题时，及时修订选型、数据范围或方法。

| 阶段 | 主要工作 | 可检查的结果 |
|---|---|---|
| 选型与数据验证 | Pi / GenericAgent 相同任务接入对比；Graphiti 小样本验证；批量采集与抽取试跑；确定测试题与标注规则 | `fingraph` 入口与 `/web` 原型；真实语料及来源记录；经运行验证的选型结论与扩量依据 |
| 系统与规模数据 | 扩充 AI 股票池及历史数据；跑通量化基线、图谱特征、预测与回测；通过 MCP 接入 TUI 与 Web | 自然语言完成公司/行业分析、股票排序与历史验证；数据与时间可核查；图谱特征可消融 |
| 实验与改进 | 完成抽取评测、Agent/RAG 对照、公开基准小规模复现及预测记录；按结果修正系统 | 可复现结果、原始输出、完整费用与耗时；典型失败分析与必要的修正验证 |
| 开源交付与汇报 | 完善安装与演示；根据实际功能和实验完成 README、录像、技术报告和 Beamer | 干净环境可运行的发布版本；自然流畅的演示；有数据和实验支持的完整汇报材料 |

技术报告需覆盖老师要求的知识抽取实验和下游原型展示，不能仅依赖演示视频。报告按论文结构完成，正文不少于 5000 字，并明确成员工作。
